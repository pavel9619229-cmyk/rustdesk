# Этап 2.0 — серверная постоплата

## Результат

Сервис `masha-auth` рассчитывает задолженность только по подтверждённой
сервером длительности удалённого управления. Базовый тариф — 1 ₽ за час.
Клиент не передаёт сумму, длительность или расчётный статус.

## Модель данных

- `access_policies` — тариф, валюта, срок оплаты, grace period,
  предупреждение и лимит одновременных сеансов;
- `operator_access_policy` — назначение политики оператору;
- `access_grants` — новый источник и вид права `postpaid_account`;
- `billing_accounts` — долг в копейках, накопленные секунды, `due_at`,
  `grace_until`, `blocked_at` и расчётный статус;
- `usage_sessions` — источник серверной длительности и защита от повторного
  учёта.

Миграция расширяет таблицы на месте. Существующие операторы, grant и
сохранённое использование этапа 1 сохраняются. Автоматического включения
постоплаты существующим операторам нет.

## Расчёт

Сумма хранится в минимальных денежных единицах:

`amount_due_minor = floor(billable_seconds × rate_minor_per_hour / 3600)`

При базовом `rate_minor_per_hour = 100` ровно 3600 секунд дают 100 копеек.
Использование чисел с плавающей точкой исключено. Heartbeat и finish
начисляют только разницу между серверной длительностью и уже записанным
`accounted_seconds`; повторная доставка не увеличивает долг.

Если heartbeat пропал, сервер завершает lease после grace period и начисляет
длительность до вычисленного сервером момента завершения.

## Доступ и задолженность

Базовые параметры политики:

- `payment_due_seconds = 86400` — 24 часа на оплату;
- `grace_seconds = 3600` — ещё 1 час до блокировки;
- `warning_seconds = 600` — предупреждение T-10;
- `max_concurrent_sessions = 1`.

До конца grace period postpaid grant разрешает доступ. После него расчётный
статус становится `blocked`, и новый сеанс без другого права получает
`payment_required`. Действующие `ad_reward`, `promo` и `admin` grant
проверяются раньше postpaid grant и сохраняют доступ.

Погашение через `admin settle` сбрасывает долг, сроки и блокировку. Реальный
платёжный webhook будет подключён на этапе 2.1.

## API

`GET /v1/access/status?operator_id=OPERATOR_ID` возвращает:

- итоговый `allowed` и причину;
- выбранный `grant_id` и `grant_source`;
- `billing_status`, `amount_due_minor`, `currency`;
- `due_at`, `grace_until`, `blocked_at`;
- `warning_at`, `warning_10_minutes`, `seconds_until_block`;
- применённый тариф и серверное время.

## Приёмка

Скрипт `services/masha-auth/test-stage-2.0.ps1` подтверждает:

1. 3600 секунд создают долг ровно 100 копеек.
2. Повторные heartbeat и finish не создают повторного долга.
3. Потеря heartbeat использует серверную длительность.
4. Предупреждение появляется ровно за 600 секунд до блокировки.
5. После grace period новый postpaid-сеанс блокируется.
6. `ad_reward`, `promo` и `admin` сохраняют доступ.
7. Погашение возвращает расчётный статус `current`.
8. HTTP status API отвечает фактическим серверным состоянием.
9. Миграция сохраняет access grant этапа 1.
